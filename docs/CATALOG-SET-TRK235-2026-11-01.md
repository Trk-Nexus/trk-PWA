## 1. 何を作るか（決まっていること）

セット（`.stlib` / `.zip`）を **1 回選ぶだけ**で、中の目録とパックをまとめて入れられるようにします。

| 項目 | 決めたこと（倉庫の返事より） |
| --- | --- |
| 拡張子 | `.stlib` と `.zip` の**両方**を受ける。**中身は同じバイト列**（r4 は sha256 `0d943e76…`・30,832,151 B） |
| 中身 | `catalog/index.json` ＋ `packs/*.stpack` ＋ `font-packs/*.stpack`（書体は `font-packs/`）＋ 任意の `set.json`・`gallery/`・README |
| 読む場所 | **目録の `packs[].file` と同じパス**（`packs/` と `font-packs/` を区別しない） |
| `set.json` | 任意。あれば `name`／`release` を表示にだけ使う。無い・壊れていても目録だけで動く |
| 照合 | **zip の中の実バイト**で sha256 を計算し、目録と違えば入れない。大きさは展開後のサイズと `bytes` を比べる |
| 上限 | セット 1 GiB・1 本 500 MB（超えたらその場で止める） |
| 入れ方 | 入れたあとは既存の「使う」で適用。**自動では適用しない**（選ぶのは人） |
| 未確認 | 実ブラウザでの操作（この環境にブラウザが無い）。**未確認と書いて配る** |

## 3. 手順

### S2. 実装（`js/pack-catalog.js`）

1. **入口**：`📦 セット（.stlib / .zip）を選ぶ`（`input type=file`・`accept=".stlib,.zip,application/zip,application/octet-stream"`）。
   選べない端末のために「すべてのファイル」で選べることも文言で案内する。
2. **判定**：拡張子を信じない。先頭 4 バイトが `PK\x03\x04`（または空 ZIP の `PK\x05\x06`）かで見る。
3. **開く**：`js/zip-io.js` の `zipOpen`（中央目録だけ読む）。`..`・先頭 `/`・ドライブ文字・重複名は既存の規則で拒む。
4. **目録を探す**：`catalog/index.json`。無ければ **1 段だけ包まれた** `<フォルダ>/catalog/index.json` を許す（展開したフォルダを再圧縮した `.zip` 対策）。2 つ以上あれば「どれか分からない」で止める。
5. **読む**：目録は CRC も確かめて読む（上限 8 MB）。`sanitizeCatalog` で今までの規則どおり削る。
6. **予告**：入れる前に「セット名・release・入れる数・合計サイズ・見つからない数」を出す（trk234 の容量表示と同じ考え）。
7. **1 本ずつ**：`packs[].file` のパスで中から取り出し（CRC 確認・1 本 500 MB 上限）、**sha256 を照合**してから `installPackFile` に渡す。すでに入っていて版も同じものは飛ばす。
8. **結果**：入れた／飛ばした／入れられなかった／見つからない を 1 行で報告。行ごとの注記も今までどおり。

## 7. やらないこと

- 外部への取得（CDN・外部 API・自動ダウンロード）。セットは**利用者が選んだファイル**だけを読む。
- 入れたパックの自動適用（選ぶのは人）。
- 目録・パックの中身の書き換え（読むだけ。sha256 は配られたままの値で照合する）。
- 既存の i18n キーの改名・削除、保存キーの変更（移行が必要になるため）。
