## 7. `.js` の受け取りを、評価しない形に変えました（M2 の対応）

レビューで、`tools/lib/skin-catalog.mjs` が `node:vm` に**ホストの `Object`・`Array` などを渡していた**ため、
次のような `.js` を渡すと**コードが実行されてしまう**と指摘を受けました（実際に `/tmp` へ書き込みが起きることを確認済み）。

```js
const p = Object.constructor("return process")();
p.getBuiltinModule("fs").writeFileSync("/tmp/escaped.txt", "pid " + p.pid);
const SKINS_WIZARD = []; export { SKINS_WIZARD };
```

**どう直したか（trk273）**

| 前（trk271・trk272） | 後（trk273） |
|---|---|
| `.js` を `vm.runInContext` で**実行**して `SKINS_WIZARD` を取り出す | `.js` を**文字として読み**、`= [` の配列、または `S["id"] = {…}` のオブジェクトを**リテラルとしてだけ**切り出す |
| `require`・`fetch` を渡さないことが「安全」の根拠 | **そもそも何も実行しない**（式・関数・テンプレート文字列は読めないので断る） |
| 読めた 1 件ごとに `id` を要求 | `S["id"] = {…}` は**鍵を `id` として補う**（生成物の形に合わせる） |

テストで、上のペイロードを渡しても**ファイルが作られないこと**、配列が読めないこと（理由を返すこと）を固定しました。

**1 行だけ足します（trk275・レビュー R8）**：同じオリジンの `/trk/`（trk219）は、保存のときに**知らないキーを捨てる**ので、trk274 で足した `skinShelfVol` も `/trk/` 側では消えます（`/trk/` の設定画面を開いて保存したときだけ。`/trk-PWA/` 側の保存には影響しません）。`/trk/` に当てる版は**保留**のままです。
また、`.js` の形は 4 通り（配列・`S["id"] = {…}`・ESM の `export`・`module.exports`）を受けることをテストしています。

> ⚠ それでも「**信頼できる生成物に限る**」という前提は残ります。誰が作ったか分からない `.js` を
> そのまま読ませる運用はしないでください（読むだけで実行はしませんが、こちらの想定外の書き方は
> すべて「読めません」で止まる＝親切ではありません）。

## 10. `/trk/` を trk219 のまま止めている間の、既知の害（R3）

**消える（書かれない）**ことがあります。

- いまのところ実害が出たという報告は受けていません（実機の記録待ち）。
- ただし「/trk/ を止めている間は、行き来すると設定が初期値に戻りうる」ことは、
  先方にも知っておいていただきたい点です。
- `/trk/` を trk273 相当へ上げれば、この食い違いは解消します（同じ白リストになるため）。
