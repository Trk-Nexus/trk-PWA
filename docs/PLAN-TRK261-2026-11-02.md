## 0. 3行まとめ

1. いまの鍵盤は **2 オクターブ固定（25 鍵・白 15 本 = 630px）**。`FIRST_MIDI = 48, LAST_MIDI = 72` の直書きで、幅も `15 * whiteW` 固定。
2. **49／61／88 鍵**は「範囲の表」と「白鍵の本数」を持つだけで足ります。難しいのは **キー割り当ての持ち方**（いまは配列の添字＝C3 からの相対）で、範囲を変えると意味がずれるので、**音番号（MIDI）で持つ形へ移行**します。
3. **MIDI キーボード**は Web MIDI API。**Chrome / Edge は対応、Safari（iPhone・iPad を含む）は非対応**です。このアプリの主な使い先が iPhone なので、**PC でだけ使える機能**として出し、非対応の端末では理由を表示します。

## 2. やること

### A. 鍵盤の広さを選べる（49・61・88 鍵）

- **範囲の表**を持つ：25＝C3〜C5／49＝C2〜C6／61＝C2〜C7／88＝A0〜C8（白鍵は 15／29／36／52 本）
- 設定に **`synthModeKeyRange`**（既定は今までどおり 25）を足し、⚙ → 🎹 シンセモードに選択肢を置く。シンセ画面の鍵盤の見出しの横にも**その場で切り替える選択**を出す
- 88 鍵は 52 本 × 42px = **2,184px**。画面に収まるなら縮小し、収まらなければ**横スクロール**（いまの `instPianoScroll` がそのまま使える。開いたときに C4 が見える位置へ寄せる）
- **キー割り当ての移行**：配列（C3 基準）→ **音番号ごとの対応表**（`{ "60": "KeyQ", ... }`）へ。読み込み時に旧配列を変換するので、**利用者の割り当ては消えません**。範囲外の音に割り当てがあっても鳴らせる（画面外であることを注記）
- 発音の入口は今のまま `noteOn(token, midi)`（トークンは `key-${code}`）

### B. MIDI キーボードをつなぐ（Web MIDI）

- シンセの鍵盤パネルに **「🎹 MIDI 入力」の 1 行**を足す：状態（未対応／未接続／接続中: デバイス名）＋「つなぐ」ボタン＋最後に受けたメッセージの表示（動作確認用）
- `navigator.requestMIDIAccess({ sysex:false })` を**ボタンの操作（ユーザー操作）で**呼ぶ。Chrome 124 以降は許可の確認が出ます
- 受け取るもの：**ノートオン/オフ**（ベロシティを音量に反映）、**サステイン（CC64）**、**ピッチベンド**（±2 半音）、**オールノートオフ（CC123）**。切断・画面を閉じるときは鳴っている音を止める
- `statechange` で抜き差しに追随。接続中のデバイス名を表示
- **非対応の端末**（Safari・iPhone/iPad・Firefox の設定なし）では「このブラウザは MIDI 入力に対応していません。Chrome/Edge のパソコンで使えます」と出す
- 自動再接続：前回許可済みならシンセを開いたときに黙ってつなぐ（`synthMidiAuto`・既定オン）。断られたら何もしない（毎回うるさくしない）

### 補足（判断の材料）

- **iPhone では MIDI が使えません**（Safari が Web MIDI に未対応・iOS の Chrome も中身は Safari のため同じ）。
  実機チェックは **PC の Chrome / Edge ＋ MIDI キーボード**が要ります。手元に鍵盤が無くても、
  テストでは偽の MIDI 入力で配線を確かめます（実物での最終確認だけが残ります）。
- 88 鍵を等倍で横スクロールにすると、スマホでは 1 画面に 8 本ほどしか見えません。
  縮小を併用すると、49 鍵（29 本）はスマホでも 1 画面近くに入ります。
- 鍵盤の広さは**表示だけ**の話で、音の高さや保存データには影響しません（割り当ては音番号で持ちます）。
