## 1. なぜ作ったか

利用者の相談（2026-10-31）：

> 「書体を容量を気にせずに配れる環境作りは Avatar-Library 側で整えられるので、こちらはそれを受け入れられる環境を検討して実装する形からですね。『目録から取り込む導線』が一番近いと思います」

書体は 1 書体 0.9〜1.5 MB あります（[`FONT-SKINS-TRK228-2026-10-31.md`](FONT-SKINS-TRK228-2026-10-31.md) §5）。アプリ本体に全部入れると、オフライン優先のままでは配布物がどんどん重くなります。
そこで **配る側**（倉庫 `trk-Avatar-Library`）に `.stpack` を置き、**使う側**（このアプリ）は**目録を1回読むだけ**で「何が配られているか」を一覧できるようにしました。

### 守った約束

| 約束 | この実装 |
| --- | --- |
| CDN・外部API禁止 | **`fetch` を使いません**。目録も `.stpack` も、利用者が選んだファイルだけを読みます（テストで `fetch`／`XMLHttpRequest`／`http(s)://` が無いことを検査） |
| 保存キー変更時は移行を書く | **保存キーを増やしていません**（目録は保存しない。開き直すと空） |
| 事実と推測を分ける | §7 に未確認を列挙 |

## 2. 使い方（利用者）

1. 倉庫（`trk-Avatar-Library`）から **`catalog/index.json`** を落とす
2. 設定 → 📦 カスタムパック → **📚 目録から入れる** → 「📚 目録（index.json）を選ぶ」
3. 一覧（名前・作者・大きさ・書体数・ライセンス・sha256 の先頭8桁）から、入れたい行の **「この .stpack を選ぶ」** を押す
4. 目録の **大きさ** と **sha256** を照合してから、いつものインストーラで入ります

- 目録の `.json` は**画面にドロップしても**読めます（`.stpack` のドロップは従来どおり `custom.js` が先に受け取ります）
- 一覧は**外部へ取りに行きません**。.stpack を自動で落とすこともありません（落とすのは利用者）

## 3. 目録の形（version 1・倉庫とアプリの取り決め）

```json
{
  "format": "trk-avatar-library",
  "version": 1,
  "name": "trk-Avatar-Library",
  "updatedAt": "2026-10-31T15:30:01.390Z",
  "packs": [
    {
      "id": "明朝の本-見本-f33b9a1d",
      "name": "明朝の本（見本）",
      "author": "trk-Avatar-Library",
      "version": "1.0.0",
      "file": "packs/sample-mincho.stpack",
      "sha256": "f33b9a1d0f544b9f135f17091df3e16d6e00a93c4d495612a0ebc8601c27ba5d",
      "bytes": 690,
      "fonts": [{ "family": "Zen Maru Gothic", "file": "fonts/a.woff2", "license": "OFL-1.1" }],
      "license": "GPL-3.0-or-later",
      "description": "見本です",
      "url": "https://example.com/pack"
    }
  ]
}
```

アプリが読む項目（**これ以外は無視します**。倉庫側が `folder`・`songs`・`warnings` などを足しても壊れません）：

| 項目 | 必須 | 見方 |
| --- | --- | --- |
| `format` | ○ | `"trk-avatar-library"` 以外は読まない |
| `version` | ○ | `1` まで。**2 以上は「このアプリでは読めない」として断る**（将来の形式変更で誤読しないため） |
| `packs[].name` | ○ | 80 文字まで。空なら、その1件だけ落とす |
| `packs[].file` | ○ | 相対パスで `.stpack` だけ。`..`・先頭 `/`・その他の拡張子は**その1件を落とす** |
| `packs[].sha256` | 推奨 | 64 桁の16進だけ受け付ける。形が違えば**空にして照合しない**（入れられはする） |
| `packs[].bytes` | 推奨 | 目録と違えば**入れない**（途中で壊れた・別ファイルを防ぐ） |
| `packs[].fonts[]` | 任意 | `family` があるものだけ。画面に「書体n」と出す（**中身はまだ使わない**。§5） |
| `packs[].license` / `description` | 任意 | 200／300 文字まで。画面に出す |
| `packs[].url` | 任意 | `https://` だけ。**リンクにはせず、項目として保持するだけ** |

上限：パック 500 件・名前 80 文字・説明 300 文字。

## 5. 書体パック（アプリ側の次の段・まだ読まない）

倉庫側は `pack.json` に次の `fonts` を書ける形を予定しています（倉庫の `font-packs/README.md`）。

```json
{ "fonts": [{ "family": "TrkZenMaru", "file": "fonts/ZenMaruGothic-Regular.woff2", "weight": 400, "license": "OFL-1.1" }] }
```

受け入れるときに必要な作業（**まだ実装していません**）：

1. `sanitizeManifest` に `fonts` を足す（`file` は `.woff2` だけ・`family` は英数字と空白 40 文字まで）
2. パックを当てたとき、`new FontFace(family, url(blobURL))` を `document.fonts.add` し、`--font` の先頭に足す
3. パックを外したら `document.fonts.delete` と `URL.revokeObjectURL` で片付ける（**漏らさない**）
4. ライセンス全文（`OFL.txt`）をパックに同梱させる（倉庫側の検査で強制）
5. 1 パック 500 MB の上限はそのまま（書体 10 本で 10 MB 程度なので余裕）
