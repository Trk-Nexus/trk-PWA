## 2. やること（案）

### A. M1：閉じる側を 1 か所に寄せる

```
async function leavePipBoth() {
  try { if (document.pictureInPictureElement) await document.exitPictureInPicture(); } catch (_) {}
  try {
    const v = core.video;
    if (v && typeof v.webkitSetPresentationMode === "function" &&
        v.webkitPresentationMode === "picture-in-picture") v.webkitSetPresentationMode("inline");
  } catch (_) {}
}
```

- `exitPip()` と `closeMedia()` の両方から呼ぶ（**書き写しをやめる**）。
- `pipActive = false` は **`pipActuallyOn()` が false のときだけ**（まだ出ていれば `webkitpresentationmodechanged` が後で合わせる）。
- ついでに `closeMedia()` の**未処理の reject**（`try/catch` は Promise の reject を拾わない）も解消。
- `pipActuallyOn()` を足す：`pipRunning({ stdElement, webkitMode })` の生の状態（`pipActive` を含めない）。

### B. R1：待ち方をイベントにする

- `waitWebkitPip(ms = 2500)`：`webkitpresentationmodechanged` を 1 回待つ Promise（**登録してから**呼ぶ・タイムアウトで実際の状態を見る）。
- `pipEnterWebkit()` は「呼ぶ → 待つ → `pipPrefer` を覚える」。
- `togglePip()`：`pipActive = ok || pipIsOn();`／トーストは `!pipActive` のときだけ。

### C. R3：押せない理由を**見える文字**で

- `#mediaPipWhy`（`<p class="mediaPipWhy hint" hidden>`）を **controls のすぐ下**に置く。
  出すのは「押せないとき」だけ（`pipSupported()` が false）。文言は `mediaPipHomeApp` か `mediaPipUnsupported`。
- `pipNode` に `aria-describedby="mediaPipWhy"`（出しているときだけ）＝読み上げでも理由が分かる。
- 4 言語の `mediaPipHomeApp` を **macOS の Dock の Web アプリ**も含む言い方に直す（Q4 の指摘に合わせる）。
