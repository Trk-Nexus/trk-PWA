## 3. 書体の組み合わせ14組・設定の細分化 — **採用の方針（こちら側の返事）**

相手の `docs/2026-11-01-書体の組み合わせとエディター設定.md` に応じる形。**app 側で決める4点**（役の数／描画の割り当て／`pack.json` に書くか／UI）への回答はこれ。

### 3.1 採用する（trk246 として実装したい範囲）

- **段階②`pair`だけ**を先に実装する（`display`＝見出し用 と `body`＝本文用の2役）。③`roles`・④`digits` は**データを受けられる形にして出すだけ**（UI は作らない）。
- 保存は **`settings.typography`**（新規・`core.settings` の中。localStorage のキーは増やさない）。書式は相手の §6 と同じ：`{ format:"trk-typography", version:1, pairing, base, scale, slots:{ display:{family,weight,…}, body:{…} } }`。
- **知らない項目は捨てる**（既存の `sanitizeSkinDef` と同じ方針）→ 古い版で読んでも壊れない。
- あて先は CSS 変数2本（`--trk-typo-display`・`--trk-typo-body`）に集約し、**見出し類**（`.brand h1`・`details.panel>summary`・`.panel h3`）に `display`、本文は従来どおり（スキンの `font` を残す）。**canvas 内（`ctx.font` を触る20か所）は今回触らない**（見え方は実機で決めるため）。
- 14組は**プリセットとして同梱**（`js/typography.js` のデータ。外部取得なし・オフライン可）。選んだ組は `pairing` に残り、**スロットは後から編集できる**。書体パック未導入の端末では families がフォールバックする（＝崩れない・見本だけ縮む）。

### 3.2 送らない（いま約束しない）こと

- `pack.json` の `skin.typography`：**書面で合意してから**という相手の意向どおり、**今は読まない**（将来 `packRuntime` で拾う）。
- 設定画面のエディター（スライダー群）：`gallery/pairings.html` の試作を**実機で見比べてから**。まずは「14組から選ぶ＋見出し書体だけ変える」まで。
- 4段階のUI・6役の全公開：②で運用して困ってから。

1. `js/typography.js`（14組のデータ＋`sanitizeTypography`＋`applyTypography`）を新規、`index.html` の「🎨 見た目」附近に欄を1つ。
