## 2. 方針（変えない約束）

1. **外部へ取りに行かない**。目録も `.stpack` も、利用者が選んだファイルだけを読む（`fetch` を使わない）。倉庫の URL をアプリに焼き込まない
2. **オリジンを勝手に変えない**。GitHub Pages 等で配るかどうかは**相談**（決めるのは利用者）
3. **保存キーは追加のみ**。移行が要る変更は書く
4. **入れる前に照合**（大きさ → sha256）。合わなければ入れない
5. **見た目を壊さない**。既存のパック一覧・インストーラの検証と容量の判定は1か所のまま

## 3. trk231（実装済み）：導入・消去の手数を減らし、入れる前に確かめられる

### 3-1. 📥 まとめて入れる（F1・F2）

- 設定 → 📦 カスタムパック → 📚 目録から入れる に **「📥 まとめて入れる」** を追加（`#catalogBundle`・`multiple`）
- **目録（index.json）＋ 好きなだけの `.stpack`** を一度に選べる。画面にまとめてドロップしてもよい
- 突き合わせは**ファイル名の末尾**（`packs/foo.stpack` ↔ `foo.stpack`）。作者・名前は目録側の値を使う
- 1件ずつ **大きさ → sha256** を照合してから入れる。**すでに入っているものは入れ直さない**
- 終わったら「入れた 3件／入れられなかった 0件／目録にない 1件」のようにまとめて出す

> ドロップの取り合いを避けるため、`custom.js` は**1ファイルの `.stpack` のときだけ**先に受け取り、2ファイル以上または `.json` を含むときは目録の側（`js/pack-catalog.js`）に渡します。

### 3-2. 導入済み・使用中の表示（F4）

- 目録の一覧の各行に **未導入／導入済み／使用中** のバッジ
- 目録の大きさと、入っているパックの大きさが違えば **「大きさが違う版」**
- 目録の上の行に **「{name}：2件（入っている 1件）」**
- 同じかどうかは**名前＋作者**（前後の空白・大文字小文字は無視）。純粋関数 `samePackAs` にしてテストしています

### 3-3. その場で「使う・消す」（F5）

- 導入済みの行に **「使う」**（＝`activatePack`）と **「消す」**（＝`deletePackById`）
- **消すときは、使っているパックなら先に外す**（設定に `packPrev` が残らないように）。順序をテストで固定
- パック一覧側の削除も同じ関数に寄せました（挙動はこれまでと同じ・確認ダイアログも同じ）

### 3-4. 🔎 中身を入れる前に見る（F3）

各行に「🔎 中身（入れる前に確かめられること）」を開けるようにしました。

- ファイル名・大きさ・**sha256 の全部**
- **書体**: family／ライセンス（OFL-1.1 など）／ファイル名
- ライセンス、入手元（`https` のみ。リンクにしない場合あり）

### 3-5. 変えたファイル

`js/pack-catalog.js`（まとめて入れる・状態・使う/消す・中身）／`js/custom.js`（`listInstalledPacks`・`deletePackById` を公開、ドロップの受け渡し）／`index.html`（`#catalogBundle`）／`js/i18n.js`（19キー×4言語）／`sw.js`／`tests/trk231-catalog-bundle.test.mjs`（12件）

## 4. trk232（実装済み）：倉庫の主役＝書体パックを使えるようにする

### 4-1. 書体を `FontFace` で登録する（F7）

倉庫には **Zen Maru Gothic 400／700 入りの「丸ゴのお茶目」**（2,935,978 B・`fonts/` に woff2 2本と `OFL.txt`）が既にあります。アプリ側だけが未対応です。

```js
/* パックを当てたとき（js/custom.js の activatePack の中） */
for (const f of man.fonts || []) {
  const face = new FontFace(f.family, `url(${URL.createObjectURL(files[f.file])})`, { weight: f.weight, display: "swap" });
  await face.load(); document.fonts.add(face); loaded.push(face);   /* 外すときに delete する */
}
root.setProperty("--font", `${family}, ${現在の --font}`);
```

必要な作業（`docs/LIBRARY-TRK230-2026-10-31.md` §5 の続き）：

1. `sanitizeManifest` に `fonts` を足す（`file` は `.woff2` だけ・`family` は英数字と空白 `._-` 40文字・`weight` は 100〜900）
2. 当てたときに `FontFace` を登録し、`--font` の**先頭**に足す（本文も見出しも同じ書体へ）
3. 外したとき・消したときに `document.fonts.delete(face)` と `URL.revokeObjectURL` で片付ける（**漏らさない**。ここをテストで固定）
4. 起動時の復元（`activePack`）でも登録し直す
5. `tests/` に「登録 → 外す → 消す」で `document.fonts` の枚数が戻ることを書く（偽 `document.fonts` で検査）

**受け入れ条件**：書体パックを入れて「使う」と、書体スキン 9 種のうち該当する見出し・本文が同梱書体で表示される。外すと元の書体に戻る。パックを消しても `document.fonts` に残らない。

### 4-2. 版（`release`）を持って、更新を見分ける（F8）

- `sanitizeManifest` に `release`（`1.2.3` の形・24文字まで）を足す
- 目録の `packs[].version` と比べて、**「新しい版があります」** を出す（入れ替えは「入れる」を押したとき）
- 目録は `release` を `version` に入れている（倉庫の `tools/build-catalog.mjs` が対応済み）

### 4-3. 実装したもの（trk232・2026-11-01）

| 提案 | 実装 | 提案と変えたところ |
| --- | --- | --- |
| `fonts` を `sanitizeManifest` で受ける | `family`・`file`・`license`・`weight`・`style` を受け、`file` は **woff2／woff**・8書体・1書体 16MB | 倉庫は woff2 だけだが、手元で作る人が `.woff` も使えるように広げた |
| 保存する | `manifestPaths` に `font` を足し、他のファイルと同じく IndexedDB へ | これが無いと「2.8MB 落としたのに 0 バイトしか残らない」ままだった（**F7 の本当の原因**） |
| `FontFace` で登録 → `--font` の先頭 | `registerPackFonts`＋`window.Trk.packFont.forSkin`。`core.applySkin` が `--font` を作るときに先頭へ | 見出しの `--font-title` は触らない（trk228 の書体スキンが見出しに指定した書体はそのまま） |
| 外したら片付ける | `clearPackFonts`（`document.fonts.delete`）＋`revokeObjectURL`。外したあと `--font` を作り直す | パックを消したとき・切り替えたときも同じ道 |
| 起動時の復元 | `initPacks` → `activatePack(id, {restore:true})` で登録し直す | 既存の復元の道に乗せた（新しい保存キーなし） |
| テスト | `tests/trk232-pack-fonts.test.mjs`（**23件**）＝検証・保存対象・登録／片付け・つなぎ方・4言語 | 偽 `document.fonts` と偽 `FontFace` で「登録 → 外す」の枚数まで見る |
| `release`＋更新表示 | `sanitizeManifest` が `release` を保ち、`versionDiffers` で目録の `version` と比較。一覧に「更新あり（1.0.0 → 1.1.0）」・「新しい .stpack を選ぶ」・「🔔 更新あり n件」 | 入れ替えは**利用者が選んだとき**だけ（自動更新はしない） |

**倉庫の実物で確かめたこと**：`font-packs/maru-go.stpack` の `pack.json` を `sanitizeManifest` に通すと **TrkZenMaru 400／700 の2件**・`release 1.0.0` になり、`manifestPaths` が **woff2 2本（1,436,276＋1,492,576＝2.79MB）** を指しました（この環境で実行）。実ブラウザでの見え方は**未確認**です。

**残っていること**：`OFL.txt`（ライセンス全文）はパックの中に残り、アプリが保存・表示するのは `family` と `license` の名前だけです。全文も持ちたい場合は、次の段で `fonts[].licenseFile` を足すのが自然です（倉庫側の契約も同時に）。

### 5-2. trk234 で実装したこと（2026-11-01）

| 案 | 実装 | 備考 |
| --- | --- | --- |
| 大きさ・合計を見せる | 一覧の上に **💾 保存 {n}個・合計 {size}（上限 {cap}）**・**上限の {pct}%** のバー・**端末の空き 約{free}**・**大きいもの: 名前 2.9 MB / …**・**使っていないもの {n}個・{size}** | 目録の一覧の概要にも「目録の合計 {size}」 |
| まとめて消す | 各パックの左にチェック。**全部選ぶ／使っていないものを選ぶ／選択を解除／選んだ {n}個を消す（{size}）** | 確認は**1回**（件数と合計）。使っているパックが混ざれば「先に外します」 |
| この目録のぶんを消す | 目録の一覧に **🧹 この目録のぶんを消す（{n}個・{size}）** | 入っているものがあるときだけ。`deletePacksByIds` を再利用 |
| パックを全部消す（❓謎設定） | **🧨 パックを全部消す**（確認2回：件数と合計 → **DELETE と入力**） | 曲リストに足した曲は消さない |
| 外すだけ | 一覧の上に **↺ パックを外す**（従来から） | 変更なし |

**気をつけたこと（実装）**：`packsChanged` は**まとめて1回だけ**／消す直前に `packDeletePlan` で「実際にまだ入っているもの」へ選び直す／数字は `packSizeText`・`packUsageInfo`・`packDeletePlan`（DOM を触らない純粋関数）に集約／上限の数え方は trk232 のまま（`packDB.usage()` は index のキーだけを読む）。

**確かめたこと**：`tests/trk234-pack-storage.test.mjs` **25件**、`npm run check` **1053 pass / 0 fail**、`check-repo` 0/0。詳細は [`PACK-STORAGE-TRK234-2026-11-01.md`](PACK-STORAGE-TRK234-2026-11-01.md)。

**未確認**：実ブラウザでのバーの伸び方、チェックの押し心地、`confirm`／`prompt` の文面、14種を入れたときの実使用量。

## 6. trk235（提案）：`.stlib`（セット）＝ダウンロード 1 回で配る

> **2026-11-01：倉庫へ要件を渡しました**（[`LETTER-TRK235-2026-11-01.md`](LETTER-TRK235-2026-11-01.md)・Drive の `trk-Avatar-Library-手紙-2026-11-01`）。
> 拡張子 `.stlib`・中身（`catalog/index.json`＋`packs/*.stpack`＋任意の `set.json`）・sha256 は中の `.stpack` の実バイト・上限 1 GiB／1 本 500 MB・受け入れ条件 A1〜A6 を提示し、Q1〜Q5 の返事待ちです。返事が来たら実装に入ります。

```
trk-set-書体まるごと.stlib        ← ZIP
  catalog/index.json              ← 目録（2〜N件）
  packs/maru-go.stpack
  packs/mincho.stpack
  README.txt
```

- アプリは `.stlib` を**ドロップ**されると、`js/zip-io.js` で中を開き、`catalog/index.json` と `.stpack` を取り出して **trk231 の「まとめて入れる」と同じ道**に流す（新しい取り込み経路を作らない）
- 上限は既存のパックの上限（1件 500 MB・合計 1 GiB）と、ZIP の展開上限（`zip-io` の制限）に従う
- **配る側**（倉庫）は `tools/build-set.mjs` で作る（`build-pack.mjs` と同じく決定的な ZIP）
- 効果：F1 が**完全に消える**（落とすのは1ファイル）。1 セット 3〜20 MB 程度を想定
- リスク：二重 ZIP（展開時に一時的に容量を使う）／巨大なセットは端末の空きを圧迫 → 「セットの大きさ」を先に見せ、**入れる前に合計 MB を出す**
