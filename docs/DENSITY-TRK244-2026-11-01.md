# 🧱 trk244：表示の密度（PCで縮小しても「詰めて多く見せる」）— 2026-11-01

利用者さんの相談（2026-11-01）：

> PC版では縮小化しても表示部分を減らして全体大きさ維持（Clementine 等基本思想を設定として）

## 1. 何を考えたか（事実）

### 1.1 trk243 までの「拡大率」

- `settings.uiScale`（50／75／100／125%、既定100）は **ステージ全体を拡大・縮小する**仕組みだった
  （`fitStage()` が設計サイズ 1920×1080 を `1/拡大率` に縮めて、その分だけ拡大して描く）。
- つまり 75%・50% は「**文字もボタンもいっしょに小さく**」で、縮小すればするほど読みにくくなる。
- 縮小の目的が「1画面に多くを出したい」だけなら、**文字を小さくせずに余白だけ詰める**ほうが実用的。

### 1.2 Clementine／MusicBee の考え方（公開されている情報からの要約＝推測を含む）

| アプリ | 缩小まわりの考え方 |
| --- | --- |
| Clementine | 左サイドバー＋タブ状プレイリスト＋**即時検索**で、窓が小さくても一覧の行数を稼ぐ。行の高さは一定で、潰すのは余白 |
| MusicBee | 一覧の行 high/low を変えて「同じ窓で何行見えるか」を調整する（Compact 的な詰め方）。フォントは変えない |

**共通する思想（本実装の目安）**：縮めるのは *余白・行間・列数*、*文字は触らない*。
→ 「表示部分を減らして全体の大きさを維持する」＝利用者さんの言葉そのままの形にした。

## 2. 実装の設計（trk244）

### 2.1 密度の4段

| 段 | 名前（表示） | 余白 `--trk-dens-pad` | すき間 `--trk-dens-gap` | 行間 `--trk-dens-line` | 棚の列 `--trk-skin-cols` | ジャケ `--trk-lib-thumb` |
| --- | --- | --- | --- | --- | --- | --- |
| `roomy` | ゆったり | 1.18 | 1.14 | 1.62 | 2 | 46px |
| `normal` | ふつう（既定） | 1 | 1 | 1.5 | 3 | 40px |
| `compact` | ぎゅっと | .72 | .8 | 1.34 | 4 | 32px |
| `dense` | ぎっしり | .55 | .7 | 1.24 | 5 | 24px |

- **`normal` は trk243 までと同じ数値**（`--trk-dens-*` の既定が 1。既定の見た目を変えない）。
- `font-size` はどこでも変えない（密度の規則に `font-size` を入れないことをテストで縛る）。

### 2.2 既存の「拡大率」との関係（ここが判断の分かれ目）

- 新しい設定 `uiScaleCompact`（既定**オン**）：オンだと **75%・50% ではステージを拡大縮小せず**、
  密度をそれぞれ `compact`・`dense` にする。→ 文字と全体の大きさは 100% のまま、見える行数だけ増える。
- **125% は従来どおり「文字を大きく」**（拡大率の役目はそれなので、密度は据え置き＝`normal`）。
  余白も広げたいときは密度で `roomy` を選ぶ（拡大率 125% のままでも効く）。
- 100% では密度だけ単独で選べる（拡大率を動かさずに `dense` にできる）。
- `uiScaleCompact` を**オフ**にすれば trk243 までの挙動（全体を小さく描く）に戻る。

### 2.3 担当の分け方

| 場所 | やること |
| --- | --- |
| `js/core.js` | `UI_DENSITIES`・`DENSITY_BY_SCALE`・`uiScaleShrinks()`・`densityFromScale()`・`uiDensityAuto()`・`uiDensityValue()`。`applyUiScale()` は `body` へ `trk-density-<段>` と `trk-scale-compact` を出し入れし、`emit("density")` するだけ |
| `css/style.css` | `--trk-dens-*` を §6〜§10 の各欄の `padding`／`gap`／`line-height`／`grid-template-columns` として使う（値は `calc(旧px * 変数)`。旧px はそのまま残す） |
| `js/ui-prefs.js` | `#uiDensity`（4段）と `#uiScaleCompact`（チェック）の配線。自動のあいだは select を `disabled` にし、`#uiDensityState`（`role="status"`）で「拡大率 {n}% から自動」を伝える |
| `index.html` | ⚙ → 🖥 画面と再生バー の trk222 ブロックの直後に2つの欄を足すだけ |

- **DOM は作り直さない**：`applyUiScale()` から `buildSkinGrid()` を呼ばない（棚を作り直すと
  スクロール位置とフォーカスが飛ぶため）。列数は CSS 側で決める。
- `emit("density", 段)` は出しておく（今後、密度に合わせて描画を変えたい担当が使える）。

### 2.4 保存

| キー | 値 | 既定 | 場所 |
| --- | --- | --- | --- |
| `uiDensity` | `roomy` / `normal` / `compact` / `dense` | `normal` | `core.settings`（`shadow_taiko_preferences_v2` の中） |
| `uiScaleCompact` | 真偽 | **真** | 同上 |

- **localStorage の新しいキーは作らない**（設定全体の中身として保存）。既にある版が読めない値を入れても `pick()` で既定へ落ちる。
- `?reset=all`（工場出荷状態）では `uiDensity = "normal"`・`uiScaleCompact = true` に戻す。
- 旧版からの移行は不要（キーを追加しただけ・既定で埋まる）＝`docs/MIGRATIONS.md` に行は足さない。

### 2.5 スマホ型での詰めすぎを防ぐ

- `.trk-mobile .libRow { min-height: 52px; }`（trk220 系）はそのまま残す＝行の高さの床。
- `body.trk-mobile.trk-density-*` で列数とサムネイルの下限を持ち上げる（ぎっしりでも 36px・4列まで）。
