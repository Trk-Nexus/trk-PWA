## 1. 実装（trk319）

### 削除の競合（同一タブ）

- 削除の開始時に、準備中の同じ候補の選択を取り消す（`choiceSeq` を進め、`choosingId` を見る）。読み込みの完了は待たない。
- 取り消された準備は保存も適用もせず、理由 `superseded` を返す。読み込んだ書体は解放する。
- 別の候補の削除は、進行中の選択を取り消さない。
- 削除が失敗した場合も、開始時に取り消した選択は戻らない。画面は保存の状態を読み直して示す（利用者には「保存しませんでした」の表示が出る）。**どの操作が勝つかは、削除が開始した時点で決める**方針。
- 候補の更新（導入）も、準備中の同じ候補の選択を取り消す。

### 他のタブとの直列化

- 選択・削除・導入を Web Locks（名前 `trk-title-font`）で一つずつ行う。タブをまたいでも順番が保たれる。
- Web Locks が使えない環境では、従来どおり直接行う（同一タブの取り消しは効く）。
- 書体の読み込みは 15 秒で打ち切る（待ち続けて、ほかの操作を止めないため）。

### 壊れた保存の扱い

- `trkTitleFontWorks` が JSON として読めない・オブジェクトでない（配列・数値など）ときは、作品の指定の書き込みを拒否する（`setWorkFont`・`setWorkLink` は `false`）。元の文字列は残る。
- 空（未設定）からは、従来どおり書ける。
- 利用者への案内（壊れた保存を退避・復旧する操作）は未実装。書き込みを拒否する（上書きしない）ところまで。

## 2. 試験

- `tests/trk318-title-font-race.test.mjs` 15 件（trk319 で版の固定を更新）。
  - 選択準備→同じ候補の削除→遅延完了：選択は復活せず、書体も残らない。
  - 別候補の削除：進行中の選択は残る。
  - Web Locks の模擬：削除は選択が終わるまで行われず、その後に削除される。
  - 削除と選択の順番（ロックあり）：選択（superseded）→削除。
  - 壊れた保存（不正な JSON・配列・数値）：書き込みを拒否し、元の文字列を残す。空からは書ける。
