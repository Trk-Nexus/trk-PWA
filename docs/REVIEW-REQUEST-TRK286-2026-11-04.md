## 3. 端末の中でできること

**呪文は 24 本**。`help` で**よく使う 5 本＋案内**、`help all` で全部、`help <語>`／`man <語>` で 1 本。

| 呪文 | すること | 呪文 | すること |
|---|---|---|---|
| `play <n/名前>` | 曲を鳴らす（行き先は #5） | `next` / `back` / `re` | 次／前／最初から |
| `list` | 曲を番号つきで並べる | `grep <語>` | 曲名と出どころから探す |
| `skin <id>` | スキンを見る／当てる | `grimoire [カテゴリ]` | スキンの一覧 |
| `volume <0-100>` | 音量 | `seek <mm:ss>` | 再生位置 |
| `repeat <mode>` / `shuffle on\|off` | 繰り返し・シャッフル | `cast <呪文>` | 続けて唱える（`;` 区切りも可） |
| `spell …` | 辞書の一覧・保存・削除 | `pwd` / `ls` / `cd` / `cat` | いまの場所・一覧・移動・中身 |
| `history` / `clear` / `echo` / `bell` | 履歴・画面消し・おうむ返し・音 | `quit` | 閉じる（Esc と同じ） |

**入力の作法**：↑↓ は履歴、Tab は補完（**打っている文字があるときだけ**・空ならフォーカス移動）、**IME の変換中は Enter／Tab／矢印を使わない**、全角で打っても通る（NFKC）、**開いている間は画面のどこにフォーカスがあっても 1 文字目を奪う**（ただし端末の入力欄と辞書は邪魔しない）。

## 4. 決めたことと、その理由

1. **`<dialog>`＋`showModal()`**：`role="dialog"`・`aria-modal`・フォーカスの閉じ込め・Esc・フォーカスの戻しを**手で書かない**（ブラウザーが返す）。背景クリックは `closedby="any"`、無いブラウザーは pointer の位置で判定。
2. **下から押し上げる**：`@starting-style`＋`transition-behavior: allow-discrete`＋`overlay`。`prefers-reduced-motion` では動かさない。
3. **スキンは板の中だけ**：`applySheetSkin()` が板の CSS 変数と `--ui-accent-ink` を差し替えるだけ。**画面全体は `applySkin` しない**（後ろの曲リストが塗り替わると「端末に当たった」ではなく「画面が変わった」に見え、閉じるときにちらつくため）。
4. **既定は閉じない**：1 回呼んで唱えて、そのまま何度も唱えられる形に。閉じたい人だけ #3 をオン。
5. **`help` は 2 段**：最初に読む量を減らす（5 本＋案内）。全部は `help all`。

## 5. 既知の限界（正直に）

- **実機で見ていない**：見た目・動き・読み上げ・スマホのキーボード。自動テストは CSS を「規則として」検査しているだけで、描画は見ていない。
- **高さはドラッグで変えられない**：3 段から選ぶ形（ご相談では「大きさの変更機能もあって良い」だったので選択式にした）。
- **`body:has(dialog[open])` で後ろのスクロールを止めている**：`:has` が無いブラウザーでは後ろが少し動く。
- **`closedby="any"` は新しい属性**：未対応のブラウザーは pointer の位置で判定する fallback を通る（判定は板の矩形の外かどうか）。
- **`cliSkinPick` は `locked` を出さない**：鍵つきスキンしか無い人には「選べるものが無い」状態になりうる。
- **`cliBell` は二重の関門**：設定がオンでも、スキンが `cli.bell:true` でないと鳴らない。「オンにしたのに鳴らない」と言われやすい。
- **辞書の名前は英小文字・数字・ハイフン 24 文字まで**（`/^[a-z0-9][a-z0-9-]{0,23}$/`）。日本語の名前は付けられない。
- **読み上げは未検証**：`aria-live`（`#cliKeyStatus`・`#cliPromptPreview`・状態行）を置いたが、実際の読み上げ量は見ていない。
- **Windows の Win+キーは OS が先に取る**：Win+D・Win+L・Win+E などは OS のもの。Win+Enter や Win+バッククォートのような空いている組み合わせを選ぶ必要がある（案内は ⚙ に出している）。
- **入力は端末が握る**（trk287）：端末を開いているあいだ、1 文字は端末が自分で入れる。そのため端末の中ではブラウザーの「元に戻す（Ctrl+Z）」などが効かない場面がある（入力欄の値は JS で入れるため）。

## 11. 追記：trk287（`p` と `:` の入力・スーパーキー）

レビュー前の点検で見つかった 2 件を、同じ版のうちに直しました。**この節だけ読めば追えます。**

### 11-1 `p` と `:` が入力できない（直した）

**原因**：trk285 の「入力を奪う」形は、**入力欄にフォーカスがあるときはブラウザーの既定の挿入に任せていた**（フォーカスが外にあるときだけ自分で足していた）。そのため、ほかの処理が `preventDefault()` した文字が**そのまま落ちる**ことがありました。

- `p` は **`KeyP`**＝アプリの「一時停止／戻る」キー
- `:` は **Shift 付きの記号**（`Semicolon`）

**直し**：**入力欄でも端末が自分で入れる**（`insertTextAt()` でカーソルの位置に挿入し、`preventDefault()`＋`stopPropagation()`）。外の操作（**P**・**/**・**`**）には渡さないので二重入力も起きません。**辞書の入力欄・Tab・出力の矢印・IME の変換中**は今までどおり譲ります。全角の `：` も NFKC で通ります。

**確かめてほしいこと**：`play` / `spell` / `seek 1:30` がそのまま打てるか。`/` を押しても設定の検索へ飛ばないか。変換中に二重に入らないか。

### 11-2 スーパーキー（Win + なにか）で登録（足した）

| 選択 | 意味 |
|---|---|
| `ctrlOrMeta`（既定） | Ctrl または ⌘／Win のどちらでも |
| `meta` | **Win／⌘（Super）だけ** |
| `ctrl` | Ctrl だけ |
| `alt` | Alt だけ |

⚙ の ⌨ パネルに「修飾キー（一緒に押すキー）」の 4 択（`#cliModSel`）と、**Windows は Win+D などを OS が先に取る**旨の案内を置きました。表示は `Win／⌘ + K` のように選んだ形で出ます。

**確かめてほしいこと**：`meta` を選んで **Win+Enter**（または空いている組み合わせ）で開閉できるか。`Ctrl` を選んだとき、⌘ では開かないこと。
