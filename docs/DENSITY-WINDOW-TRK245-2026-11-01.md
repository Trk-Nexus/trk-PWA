# 🪟 trk245：密度を「窓の広さで自動」に ＋ 📐 曲リストの高さを画面に合わせる — 2026-11-01

trk244（表示の密度）の続きです。利用者の指示（2026-11-01）：

> 1. 密度を「窓の広さで自動」に
> 2. 曲リストの高さを画面に合わせる

## 1. 事実（trk244 までの状態）

- 密度は4段の手動選択で、**拡大率 75%・50% のときだけ**自動（`uiScaleCompact`）。窓の大きさ自体は見ていなかった。
- `#libList` の高さは `css/style.css` に **2か所**あった：
  - `§8` の `height:640px`
  - `#fxDock` の塊のうしろに `#libList{height:320px}`（**あとから効くので、実際に効いていたのは 320px**）
  - どちらも固定値なので、拡大率で縮めて設計が広くなってもリストは伸びなかった。
- `#stage` は 1920×1080 の設計px固定（`fitStage()` が拡大率に応じて設計サイズを変え、窓に合わせて等倍縮小する）。だから**設計pxで決めないといけない**（`vh` を入れると縮小率でもう一度縮んで変になる）。

## 2. 実装

### 2.1 密度の「自動」（`uiDensity: "auto"`）

- 選択肢を5つにした（**既定は `auto`**）：自動（窓の広さに合わせる）／ゆったり／ふつう／ぎゅっと／ぎっしり。
- 決め方（`densityFromWindow(width, height)`＝純粋関数）：
  - 面積 `mpx = 幅 × 高さ / 100万px²`
    - `mpx ≥ 2.6` → `roomy`（2560×1440 あたり）
    - `mpx ≥ 1.0` → `normal`（**1920×1080・1440×900・1366×768 は従来どおり ふつう**＝既定の見た目を変えない）
    - `mpx ≥ 0.45` → `compact`（1200×700・1000×600）
    - それ以外 → `dense`
  - **幅が 900px 未満**（半画面スナップ・小さな窓）は、もう1段詰める（高さではなく幅で判断する）
  - 読めない値（0・NaN・文字列）は `normal` に落ちる（壊れた値で画面が崩れない）
- 優先順位：**①75%・50% の「縮小＝詰める」（拡大率）→ ②`auto` なら窓 → ③選んだ段**。
- リサイズでも見直す：`fitStage()` が `applyDensityClasses()` を呼ぶ（保存しない・棚を作り直さない・`emit` も出さない）。等倍の laptop では段が変わらないので、**日常の見え方は trk244 のまま**。

### 2.2 曲リストの高さ（`--trk-lib-h`）

- `libListHeight(designHeight) = clamp(320, designHeight − 440, 900)`（設計px。440px はバナー・見出し・ツール・詳細欄のぶん）
- `fitStage()` が `--trk-lib-h` を `:root` に置く。CSS は `#libList{height:var(--trk-lib-h,640px)}`（**js が無いとき・初回描画は 640px**）。
- 結果：等倍 1080 → **640px**（trk222 までの設計どおりに戻る）／125%（設計 864）→ 424px／75%・50%（設計 1440・2160）→ 900px（上限）。
- **`#fxDock` のうしろに有った `#libList{height:320px}` は削除**（上書きになっていたもの）。コメントで行き先を書いておく（また固定値を置かないために）。
- スマホ型は `.trk-mobile #libList{height:auto}` が勝つ（実ピクセルで並べるので触らない）。

## 4. テスト

`tests/trk245-density-window.test.mjs`（**13件**）
- しきい値（2560×1440→roomy／1920×1080・1440×900・1366×768→normal／1200×700・1000×600・900×500→compact／800×500→dense）
- 幅 900px 未満で1段詰める／高さは見ない／壊れた値は normal
- `uiDensityValue` の優先順位（75% の詰めが最優先・手動の段が勝つ・知らない値は auto）
- `libListHeight` の床・上限・異常値（`0・NaN・"x"` でも 320px）
- `fitStage` が `--trk-lib-h` と密度のクラスをそろえる／リサイズで段が変わっても**保存しない**
- CSS：`height:var(--trk-lib-h,640px)`・**後から `#libList{height:…}` を書かない**・スマホ型は auto
- 設定欄の `auto` が先頭・body には `trk-density-auto` を作らない（クラスは4つだけ）・ui-prefs は i18n キー経由・4言語

`tests/trk244-density.test.mjs` は同じ commit で更新（既定が `auto` になった／`#libList` の高さの assertions）。

## 5. 見送り（次）

- **縦長デスクトップで余る上下の余白**：`#stage` の設計高さは 1080 固定なので、窓が縦長でもリストは伸びない（`fitStage` が設計サイズ自体を変える必要＝プレイ中の盤面に触る）。`libListHeight` は「設計高さ」を見る作りにしたので、設計可変が決まればそのまま乗る。
- 窓の広さのしきい値は**計算で決めた値**（実測・実機確認はしていない）。
- 密度は再生バー・ゲーム画面には掛けない（trk244 と同じ）。
- `settings.uiDensity` の既定が `normal` → `auto` に変わった（**保存済みの人がいる端末はそのまま**。`?reset=all` では `auto`）。
