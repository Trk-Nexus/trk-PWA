# trk260：開いた直後が「枠だけ・文字なし・ボタンが効かない」を直した（2026-11-02）

> 依頼者の報告：trk! を開くと、**枠と色は出るが文字が入っていない**。曲リストも空、ようこそも出ない。
> 右下の X／GitHub Issues／Privacy／Credits は押せる。言語は 4 つ選べるが**文章は変わらない**。⛶ も無反応。
> 再現した配布物：`trk-standalone-2026-11-01-trk248.zip`（同じ症状は **trk245〜trk259** の配布物すべて）。

## 1. 何が起きていたか

`js/core.js` は **IIFE**（`(() => { … })();`）で、先頭の 57 行目に `fitStage();` がありました。
`fitStage()` は曲リストの高さを `libListHeight(H / z)` で決めますが、その関数が使う

```js
const LIB_LIST_PAD = 440, LIB_LIST_MIN = 320, LIB_LIST_MAX = 900;   // js/core.js の 1800 行台
```

は **同じファイルの後ろ** で宣言されています。宣言より前に行った呼び出しは

```
ReferenceError: Cannot access 'LIB_LIST_MIN' before initialization
```

となり、**core.js の残り全部が実行されません**。止まった先にあったのは：

- `settings`（設定の入れ物）の作成
- `applyLanguage()`（`data-i18n` の文字を辞書で埋める）
- 画面の配線（`⛶`・言語の切り替え・設定を開く…）
- `window.Trk.core` の公開

後続のファイル（`library.js`・`main.js`…）は `window.Trk.core` を前提にしているので、
**次々に `Cannot read properties of undefined (reading '$')` で落ちる**。結果、CSS だけが効いた
「枠と色はあるが中身が無い画面」が残りました。フッターの `<a>` は React も JS も要らないので押せます。

### 見た目と一致していたこと

| 症状 | 説明 |
| --- | --- |
| `Language` の見出しがそのまま | 辞書の差し込みが走っていない（HTML の初期値が見えている） |
| BPM／Offset／Seed・MANUAL…CATCH・Easy/Normal/Hard は見える | どれも HTML に直書きされている初期値 |
| 曲リストが空・ようこそが出ない | `library.js` と `main.js` が落ちている |
| 言語を選んでも文章が変わらない | 変更の受け口（`main.js`）が配線されていない |
| `⛶` が効かない | 同上 |
| フッターのリンクだけ押せる | 素の `<a href>` |

## 2. 直し方

**最初の `fitStage()` を、ファイルの最後（すべての `const`・関数を読み終えた後）へ移しました。**

```js
addEventListener("resize", fitStage);   /* 窓の大きさが変わったときは今までどおり */
…
/* ファイルの末尾 */
fitStage();                             /* 最初の寸法合わせはここで 1 回だけ */
```

`fitStage()` の中身・`--trk-lib-h` の値・密度の決め方は**変えていません**。
変えたのは「読み込み時に呼ぶ位置」だけです。

## 3. 見張り（`tests/trk260-boot.test.mjs`）

同じ罠を **依存パッケージ無し** で見張ります。

1. `js/**` を走査し、**トップレベルで呼んでいる `NAME();` が、後ろで宣言する `const`/`let` を
   （呼び先の関数を 3 階層までたどって）使っていないか**を検査
2. `js/core.js` のトップレベル `fitStage();` が **1 回だけ・`LIB_LIST_MIN` より後ろ**にあること
3. `data.js` → `core.js` の順で読み込まれていること（`window.Trk.data` を使うため）

壊し試験：`fitStage();` を先頭へ戻すと **1 が 1 件・2 が 2 件 FAIL**（実際に確認）。
戻すと 5/0。

## 5. 影響と、まだ残ること

- **配布物の作り直しが必要**：trk245 以降の ZIP（trk248・trk259 を含む）は、**初回に開くとこの状態**。
  すでに端末へ入っていて Service Worker のキャッシュで古い版が動いている場合は、
  そのままでは気づきにくい（新しい ZIP を開いたときに出る）。
- **公開サイトも同じ**：Pages は毎回ビルド無しで同じファイルを配るので、
  キャッシュを消して開き直すと trk259 までは同じ症状になる。trk260 を配れば直る。
- 実機での最終確認（言語・曲リスト・ようこそ・`⛶`・目録の版・進捗の分母）は、
  `DEVICE-CHECK-R10-2026-11-02.md` の用紙で trk260 に対して行う。
