## 0. 結論（3 行）

1. **書体の製作・追加・ライセンス、スキンの製作、目録とセットの組み立て、`gallery/` の 3 枚は、ミュージアム（倉庫）側**が持ちます。
2. **trk-PWA はアプリ本体（PWA）** に専念します（読む・入れる・選ぶ・消す・遊ぶ。中身は作りません）。
3. 受け渡しの形（目録の項目・L16・セット・`tools/check-set.mjs`）は**両方の共有財産**です。変えるときは**先に書面で知らせます**。

## 1. なぜ書面にするか

- trk233 の書体パック 14 種、r5 のセット、r6 の 2 分割のように、**相手の作業を待つ段**が増えました。段をまたぐたびに「どちらが何をするか」を口約束で確認していて、記録が残っていません。
- 「アプリ側が書体を作る」「倉庫側がアプリを直す」という**取り違え**を防ぐためです。
- ここに書いたのは、**いまの状態の確認**（事実）と、**これからの予定**（提案）を分けてあります。

## 3. 線の引き方（3 つの原則）

1. **中身は作らない。** trk-PWA は書体もスキンも作りません。ミュージアムはアプリのコードを直しません（読む・呼ぶだけ）。
2. **形は共有する。** 目録の項目（L7・L10・L11・L15・`weight`・`bytes`）、L16 の受け入れ条件、「これから入る分」の数え方（`setPending`）は**両方が同じ意味**で使います。
3. **相手の領域の決定は相手が持つ。** セットの分割・目録の絞り方・`gallery` の文言はミュージアム。アプリの画面・文言（`js/i18n.js` の 4 言語）・保存の形は trk-PWA。

### 4-1. `tools/check-set.mjs` の契約（trk240 で `version: 2`）

ミュージアムの `tools/check-set-app.mjs` が、こちらの道具を**写しを持たずに呼びます**（返事8 §3）。
そのため、**次の 4 つは勝手に変えません**。

| # | 固定すること | いまの値 |
| --- | --- | --- |
| ① | 呼び方 | `node tools/check-set.mjs <セット> [--hash] [--have=<目録.json>] [--json]` |
| ② | 終了コード | `0`＝そのまま入れられる／`1`＝食い違いあり／`2`＝開けない（ファイルが無い・ZIP でない・目録が無い などを含む） |
| ③ | `--json` の意味 | 1 行の JSON。`tool`＝`check-set`・`version`・`ok`・`problems`・`reason`・`packs[]`（`ok`／`reason`／`sha256`）・`missing[]`・`pending`（`count`／`bytes`／`ids`／`skip`） |
| ④ | `--have` の形 | `{packs:[{id,name,author,version,bytes}]}` か、その配列 |

- **増やす**とき（新しいフラグ・新しい項目）は**先に知らせます**（相手は無視できるので赤になりません）。
- **減らす・意味を変える**ときは、相手の CI が赤になるので**必ず先に相談**します。

## 6. ミュージアム側に残っている宿題（こちらからは触りません）

1. 追加 14 種 → **L16** → 目録 → `gallery/` の 3 枚 → **r6 を 2 つ**（はじめて・書体）。
2. `gallery/fonts.html` の見出しを **家族名（family）** にそろえる（r5 のバイト列を守るため、r6 で）。
3. `note` は **25 文字くらい**（30 文字超は `build-catalog` が ℹ で知らせる）。

## 7. 両方に効く約束（変えない）

- **CDN・外部 API を使わない**（書体も Google Fonts を実行時に読まない）。オフライン優先。
- **オリジンを勝手に変えない**（保存データが移りません）。
- **GPLv3 のクレジットを消さない**。
- **金・Secrets・ストア・独自ドメインは相談**。`force push` と `main` への直接 push はしない。
