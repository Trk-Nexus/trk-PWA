## 1. 何を変えたか（1 点だけ）

r6 は**はじめてセット（約 7 MB・書体 5 本）と書体セット（全部・書体 29 本）**の 2 つになり、
**はじめてセットの 5 本は書体セットにも入ります**（倉庫の返事6 §2）。

そのため、2 つ目を選んだときに trk235 のままでは **確認の大きさが水増し**されていました
（入るのは 24 本なのに「29 本・60 MB」と出る。実際には中の 5 本は飛ばすのに、合計には入っていた）。

| | trk235 まで | trk239 |
| --- | --- | --- |
| 確認に出す数 | `plan.packs` の全部 | **これから入る分だけ**（`setPending`） |
| 確認に出す大きさ | 目録の合計 | **これから入る分の合計** |
| すでに入っていて版も同じもの | 飛ばす（ただし数と大きさには入っていた） | 飛ばす（数と大きさにも入れない） |
| 版が違うもの | 入れる | 入れる（飛ばさない＝更新を取り逃がさない） |
| 文言 | `catalogSetConfirm` | 飛ばす分があるときは `catalogSetConfirmSkip`（4 言語） |

`setPending(plan, installed)` は DOM を触らない純粋関数で、`window.Trk.packCatalog.setPending` から使えます。

```js
setPending(plan, installed) -> {
  pending: [ { entry, zipEntry } … ],   // これから入る
  skip:    [ { entry, zipEntry } … ],   // すでに入っていて版も同じ
  bytes:   Number,                      // pending の合計（skip は数えない）
}
```

## 2. 受け入れの道具を作りました（`tools/check-set.mjs`）

倉庫の `tools/verify-set.mjs` は倉庫側の決めごとで検査します。こちらは**アプリのコードそのもの**
（`js/zip-io.js` と `js/pack-catalog.js`）を読み込んで同じセットを開き、**アプリが何と表示するか**を先に出します。

```sh
node tools/check-set.mjs <セット.stlib | セット.zip> [--hash] [--have=<目録.json>]
```

| 出すこと | 中身 |
| --- | --- |
| 開けるか | `openSet` の結果（`catalogSetNoCatalog` などの理由もそのまま） |
| セット名・版 | `set.json` があれば名前と `release`、無ければ目録の名前 |
| 数 | 目録のパック数 → 入れる本数・合計・形が合わず外した数・入っていない数 |
| 1 本ずつ | 大きさ（`setEntryCheck`）。`--hash` を付けると**実バイトの sha256** も照合 |
| `--have` | すでに入っている目録と突き合わせ、**これから入る／飛ばす**（アプリの `setPending` と同じ数え方） |

終了コード：0＝そのまま入れられる／1＝食い違いあり／2＝開けない。
**外へは取りに行きません**（読むのは渡されたファイルだけ）。

## 6. r6 が届いたら（手順）

1. `node tools/check-set.mjs trk-first-set-…-r6.stlib --hash` → 0 を確かめる
2. 続けて `node tools/check-set.mjs trk-font-set-…-r6.stlib --hash --have=<はじめてセットの catalog/index.json>` → **「これから入る／飛ばす」**が想定どおりか
3. 実機で 2 つを続けて入れる（はじめて → 書体）
   - 1 回目の確認：4〜6 本・約 7 MB
   - 2 回目の確認：「すでに入っていて版も同じ n 本は飛ばします」付きで、**書体セットの残りだけ**の数と大きさ
4. 入れたあと：📚 目録から入れる が**そのセットの本数どおり**（「見つからない」が出ない）、🔤 入れている書体 の行数が増える
5. 書体が当たるか・太さの切り替わり・ライセンス全文・一覧の見え方（§4-2 の残り）
