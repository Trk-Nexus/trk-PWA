## 2. 入れたもの

### 2.1 ロック画面（MediaSession）

- `navigator.mediaSession.playbackState` を `none` / `paused` / `playing` で**実際の再生に合わせて**更新します（`js/media-player-mode.js` の `updateMediaSession()`）。止まっているのに「再生中」の絵が出る（逆も）を避けるためです。
- 絵は **192 と 512 の 2 サイズ**（`icons/icon-192.png`・`icons/icon-512.png`）。端末が好きな大きさを選べます。
- 位置（`setPositionState`）は従来どおり**離散の出来事のときだけ**（毎 `timeupdate` では呼ばない）。

### 2.2 読み込み中・詰まり・失敗（無期限にしない）

- `waiting` → 「⏳ 読み込み中…」／`canplay`・`playing` → 消す。
- `stalled` は**3 秒**たっても進まないときだけ「⏳ 読み込みが止まっています」。
- `error` → 「この曲を再生できませんでした（形式かファイルを確かめてください）」＋ **⟳ もう一度**（`retryPlayback()`）。
- 再試行の元が無いときは「読み直す元のファイルがありません」と言い、押しても何も起きない状態を残しません。

### 2.3 キュー（次に再生・最後へ・外す）

- 保存は `settings.mediaQueueNext`（**曲の key だけ**・最大 100・重複なし）。壊れた値は `core.cleanMediaQueue()` が捨てます。
- 曲の行に **⏭（次に再生）／＋（キューの最後へ）**、手動キューの行に **✕（外す）**。押した曲を先頭へ移すので、同じ曲が二重に入りません。
- 手動のキューはキューの上に「⏭ 次に再生（手動）」として出し、下に「ここから下は通常の順番」と区切ります。
- 次へ進むときは手動のキューを**先に消化**し、消化したら消えます（曲が消えていたら黙って捨てる）。シャッフル中でも手動のキューは先です。

### 2.4 キューからプレイリストを作る

- キューの見出しに **💾 このキューでプレイリストを作る**。押したときだけ `window.Trk.library.createPlaylistFromSongs(name, keys)` を呼びます。
- 名前は 40 文字まで（空なら「キューから作ったリスト」）。重複は畳み、**500 曲まで**。保存に失敗したら作った分を**巻き戻します**（`{ ok:false, reason:"save" }`）。
- 曲ファイルは動かしません（プレイリストは key の並びを持つだけ＝従来のプレイリストと同じ）。

### 2.5 続きから再生の知らせ

- 「前回の続き（{t}）から再生します」／巻き戻しを使うときは「{t} から、{s} 秒戻して再生します」。**何が起きたかを 1 行**出します（黙って途中から鳴らない）。

### 2.6 曲間のつなぎ（どちらも既定オフ）

- **ギャップレス**（`settings.mediaGapless`・既定 `false`）：端末内のファイルの曲だけ、次の曲を `muted` の別要素で**先に読み込んでおく**（音は出さない・曲を変えたら URL を捨てる）。曲が変わると `disposeGapless()`。
  - **正直な但し書き**：`library.js` の `selectSong()` は次の曲の `src` を待ってから入れるため、**完全な無音の連結は保証しません**。読み込みと復号の待ちを前もって済ませる、という範囲の改善です。文言もそう書いています。
- **フェード**（`settings.mediaCrossfade`・既定 `0`＝オフ・0〜12 秒）：曲の終わり N 秒をかけて `video.volume` を閉じ、次の曲の頭を短く立ち上げます。
  - **曲を重ねません**（2 本目の `<audio>` を作らない）。音量だけを触り、設定の `musicVolume` は変えません。

## 4. 見てほしいところ（実機・実ブラウザは未確認）

1. ロック画面・イヤホンの操作で、**止めたときに絵が「一時停止」に戻る**か（曲名と絵が食い違わないか）。
2. 通信の遅い曲・大きい曲で、**「⏳ 読み込み中…」が残り続けない**か。詰まったときに ⟳ でもう一度できるか。
3. ⏭ で入れた曲が**次に鳴り、鳴ったらキューから消える**か。シャッフル中でも同じか。
4. 💾 で作ったプレイリストが、曲リストの側に**そのまま出る**か（名前・曲数）。
5. フェードを 5 秒にして、**曲が重ならない**（2 曲同時に鳴らない）こと。ギャップレスは**曲間が少し短くなる**こと（無音がゼロになるとは限らない）。

## 5. やらないこと（理由つき・クラウド版ができたら候補に戻る）

| 非目標 | いまやらない理由 | クラウド版ができたら |
| --- | --- | --- |
| **配信**（ストリーミング再生） | 曲は**端末の中のファイル**をそのまま鳴らす作りです。配信にすると、著作物を誰のサーバーから誰へ送ったのかを扱うことになり、権利と費用の話が先に来ます。いまの「ファイルを置けば鳴る・置かなければ鳴らない」は、その話を**持たない**ための形です | 自前の置き場所と帯域の当てがついたら、**同じプレイヤーの画面のまま**供給元だけを差し替える形で候補に |
| **キャスト**（テレビ・スピーカーへ送る） | 送る＝**端末の外へ音を出す**ことなので、「曲は端末の外へ出さない」という約束と正面からぶつかります。受け側の実装（DLNA・Chromecast）ごとに、送る形式・止め方・失敗の伝え方も別々に作る必要があります | 家庭内 LAN の中だけで送る形なら、**外へ出さない**約束を保ったまま検討できます（送り先の許可・送ったことの表示・止め方の 3 点を先に決める） |
| **アカウント同期**（別の端末と揃える） | いまは**この端末の保存だけ**が真実です（書き出し・読み込みは ⚙ の 💾 で手動）。同期を入れると、誰の何をどこに預かるかが増え、端末を変えたときの「どちらが正しいか」の決め方も要ります | アカウントを持つ版では、**プレイリストと「次に再生」の並び**だけを同期の候補に（曲ファイルは同期しない・しおりは端末ごと） |

**共通の考え方**：3 つとも「できない」ではなく「**いまの約束（端末の中だけ）を守る限り、しない**」。約束の外側（クラウド版）を作るときに、上の表の右の列から拾えば同じ画面のまま広げられます。
