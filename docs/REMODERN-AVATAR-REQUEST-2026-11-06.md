# trk-re-modern からの要望への受け皿（2026-11-06）

> 状態：**提案・受け皿（未合意）**。この文書は、trk-Avatar-Library 側の要望に対して PWA 側が「どこまでできて、何を決める必要があるか」を整理するためのものです。**実装・公開・合意はまだありません。** 現行コードは変えていません。

## 1. 要望の要点

trk-Avatar-Library の文書（2026-11-06 時点・PR #39 でマージ済み）から、PWA 側に関係する点は次のとおりです。

| # | 要望（Avatar 側の文書） | 出典 |
|---|---|---|
| R-1 | 書斎・基地の**領域別スキン**（共通・書斎・基地を独立して選ぶ）。ただし**PWA との検討が必要な提案**で、対応済みとはしない | `docs/trk-re-modern-concept.md` §2・`docs/re-modern-research/03-catalog-and-spaces.md` §4 |
| R-2 | 見出しに**書体（DotGothic16 系）を PWA で限定して供給**する方法（字種・復元を含む）。現状は未解決 | `concept.md` §5 |
| R-3 | 「スキンのおすすめ」ノーツ設定は共通ノーツに保存され、**スキンを変えても自動では戻らない**。安全な案内が必要 | `concept.md` §5 |
| R-4 | 適用前に対象と影響範囲を示し、**明示選択・解除・復元・失敗時の既存表示**を用意する | `03-catalog-and-spaces.md` §4 |
| R-5 | 未知の ID・未対応の版・壊れた値を受けたときは、利用者データを**勝手に消さず**安全な既存表示に落とす。旧版への移行・保存・バックアップ・復元を合意してテストする | `03-catalog-and-spaces.md` §4 |

Avatar 側の方針：PWA 側の未合意の仕様は、Avatar 側の記録だけでは承認できません（`docs/trk-re-modern-guidelines.md` §6・§9）。したがって、この文書は PWA 側の**合意の入口**です。

## 2. PWA の現状（確認した事実）

確認したのは、このリポジトリの `main`（PR #96 マージ後）です。ソースを読んだ結果で、全画面の操作検証ではありません。

- **書斎の読書テーマ**：`js/study-room.js` の `STUDY_THEMES`（plain・paper・…・staff の 30 種）と `studyPrefs.theme`。本文テーマは書斎の読書設定そのもの。
- **共通の色**：`--ui-*` の参照が `css/` に約 620 箇所。書斎の開くボタンは共通色を使うが、書斎本体は固定色・固定の system 系の書体指定を多く持つ（Avatar 側の研究記録の確認と一致）。
- **基地**：`js/media-player-mode.js` が作るメディアプレーヤー入口。映像・字幕・画中画・退出を含む。
- **書体の役割**：`js/typography.js` は `display`・`heading`・`body`・`caption`・`numeral`・`accent` の 6 役。ただし `heading`・`caption`・`numeral`・`accent` は「保存できる形にしてあるが、まだ使いません」と明記されている（同ファイル 14 行付近）。見出し限定の供給（R-2）は、この枠を使えば設計の余地がある。
- **「スキンのおすすめ」**：設定の `presetSkin`（`js/i18n.js`）。共通ノーツに保存される既存の仕組み。

## 3. 論点と選択肢（番号つき・未決）

各論点の推奨は、**小さく始めて段階を踏む**方向です。決めるのは依頼者です。

### Q1. 領域別スキン（R-1）
1. **今回は見送る**：共通スキンのみ。現状維持。
2. **書斎の外枠だけ先に独立**（本文テーマ・文字設定は触らない）。
3. **書斎と基地を両方とも独立**（影響が最も大きい。基地の映像・字幕の守りを先に設計）。

**推奨**：1 → 2 の順。3 は設計と検証の量が大きいため、2 の実績の後。

### Q2. 見出し用の書体（R-2）
1. **見送る**：見出しは系統フォント（system 系）のまま。
2. **見出し（heading 枠）だけに限定してパックで供給**：`typography.js` の未使用の枠を使う。書体の上流リンク 404 と配布物の整合を先に確認（Avatar 側の記録どおり）。
3. **他の書体も含めて一般化**：書体選択の仕組みを広げる。影響が大きい。

**推奨**：Avatar 側で上流と権利を確定させてから、2。その前に 1 のまま。

### Q3. 「スキンのおすすめ」の扱い（R-3・R-4）
1. **現状維持**：説明文の改善のみ。
2. **適用前に影響範囲を表示し、元に戻す操作を追加**（前の値を保持する方法を含む）。
3. **適用を別の操作（スキンの選択とは分けて）に変える**。

**推奨**：2。既存の保存データの互換と、旧版での挙動の確認を先に行う。

### Q4. 返事の置き場所
1. **この docs ＋ Drive の同じ場所に写し**（これまでと同じ形）。
2. **docs のみ**。

## 4. 段取り（ゲート付き）

| 段階 | 内容 | 進む条件 |
|---|---|---|
| 0 | この受け皿（本文書）の確定。Q1〜Q4 の決定 | 依頼者の決定 |
| 1 | 受け口の設計書（保存形式・既定値・優先順位・復元・旧版・未知 ID の扱い） | 段階 0 の決定。Avatar 側と設計を照合 |
| 2 | 実装（選んだ範囲だけ）と自動テスト | 設計書の合意 |
| 3 | 実機・実環境の確認（iPhone・Android・PC、狭い画面、200% 拡大、強制色、オフライン） | 段階 2 のテスト通過 |
| 4 | Avatar 側の見本・記録の更新（対応済みと書くのは段階 3 のあと） | 段階 3 の記録 |

**注意**：段階 0 の前に、スキン・書体・保存の実装は始めません。

## 5. 検証の計画（未実施）

- 利用者・障害のある人を含む確認は、Avatar 側の計画と合わせる。

**未実施**：上記すべて。この文書の時点で、対応済みとは言いません。
