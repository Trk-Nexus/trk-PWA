### 1-1. 倉庫の相談（§3）への答え

| 相談 | こちらの実装 |
| --- | --- |
| 起動時にパックを全部読んで、どのパックの書体か分かる形 | **賛成。ただし「起動時」ではなく「開いたとき」に作り直します**（保存しない） |
| 材料はもう入っている | そのとおり。`packDB` の `manifest.fonts` から作るので**新しい保存は要りません**。Blob（書体本体）も読みません（名前と大きさだけ） |
| 保存するか | **しません**。パックを消した・入れ替えたときに古い行が残るため（倉庫の注意 4 と同じ判断） |
| 索引のキー | **`family|weight`**（倉庫の L16 が目録全体で重複を止めているので、これで足りる） |
| ひとこと・タグの出どころ | **`pack.json` が優先、無い項目だけ目録で補う**（古い 15 パックは `pack.json` に書いていないため）。行そのものは「入っているもの」が正 |
| 「使う」の意味 | **その書体が入っているパックを当てる**（`activatePack`＝スキンごと切り替わる）。書体だけの差し替えはしません（今の作りに合う方） |
| 目録を控える方式 | 併用していません。目録は「配る側の一覧」なので、**画面に出すのは入っているもの**だけ。目録は**補い**にだけ使います |
| 1 パック 8 本まで・既定 400 | そのまま守っています（`PACK_FONT_MAX = 8`・`weight` 無しは 400） |
