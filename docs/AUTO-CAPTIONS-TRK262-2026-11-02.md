# 🗣 自動字幕の使い方と、trk での考え方（trk262・2026-11-02）

> この文書は「**音声から自動で字幕を出したい**」ときの案内です。
> trk は**音声認識を持ちません**（マイクも使いません）。代わりに、お使いの **OS やブラウザーの自動字幕**を使います。
> 画面の 💬 字幕 パネル →「ℹ 自動字幕について」からも、この文書と同じ要点を読めます。

---

## 1. 先に結論（3行）

1. trk の中で音を聞き取って字幕を作ることは**しません**（できない理由は §5）。
2. 自動字幕は **Windows 11／macOS／Chrome／Android の「ライブ キャプション」**で出します。**字幕は画面の下**（OS の設定で上）に、**trk の外側**として重なります。
3. 「この曲の字幕を正確に出したい」なら、**SRT／VTT ファイルを用意して 💬 字幕 に入れる**のがいちばん正確です（オフライン・端末内・遅延調整つき）。

---

## 2. 4つの選び方

| 使うもの | 対応 | 手順 | 初回だけ必要なもの |
| --- | --- | --- | --- |
| **Windows 11 のライブ キャプション** | Windows 11 **22H2 以降**。**日本語あり** | `Windows + Ctrl + L`（または 設定 → アクセシビリティ → キャプション） | 音声を端末内で処理することへの**同意**と言語パック（約 100MB）。以後はオフラインでも動く |
| **macOS のライブキャプション** | **Apple シリコン**・macOS 14 以降（日本語は Sonoma 以降） | システム設定 → アクセシビリティ → ライブキャプション | 言語データのダウンロード。**マイクを使うときは OS のマイク許可** |
| **Chrome／Edge のライブキャプション** | PC の Chrome（Edge も同系） | 設定 → ユーザー補助（アクセシビリティ）→ ライブキャプション | 言語パックのダウンロード（認識は端末内） |
| **Android のライブキャプション** | 対応端末 | 設定 → ユーザー補助 → ライブキャプション | 端末により異なる |

- どれも**アプリ（trk）の権限ではありません**。OS かブラウザーの設定です。trk はマイクの許可を求めません。
- **字幕が出る場所**：Windows／macOS は**画面の下**（設定で上にも動かせる）、Chrome は**ブラウザーの窓の下**。trk の映像の上に**OS が重ねる**形なので、trk の「字幕の置き場所」「大きさ」では動きません。
- **遅延**：自動字幕は**声のあとから**出ます（0.5〜2 秒ほど遅れます）。trk の字幕の「遅延」で合わせられるのは、**trk が描く字幕（SRT/VTT）だけ**です。

---

## 3. 権限と仕組み（安心して使うために）

| 項目 | どうなっているか |
| --- | --- |
| マイク | **trk はマイクを取りません**（`getUserMedia` を呼びません）。OS のライブキャプションが「マイクも聞く」設定のときだけ、OS がマイクの許可を尋ねます |
| 音の行き先 | Windows のライブ キャプションは**端末内で処理**（同意のうえ、言語パックを一度だけ取得）。Chrome も**認識は端末内**。macOS も**端末内** |
| 通信 | 初回の言語パックのダウンロードだけ通信します。以後はオフラインでも動きます（Windows／macOS／Chrome） |
| 保存 | 自動字幕の文章は**保存されません**（Windows も macOS も、字幕の履歴は残しません）。trk も何も保存しません |
| 止め方 | 同じショートカット（Windows は `Windows + Ctrl + L`）か、設定のスイッチを切る |

> ⚠ どうしてもブラウザーの中だけで音声認識をしたい場合、Web Speech API がありますが、
> **マイク入力しか使えない**（`SpeechRecognition.start(track)` は Chrome 139 以降の実験的な追加で、Safari・Firefox・多くのスマホは不可）、
> しかも**認識はブラウザーの提供元のサーバー**を使うものが多く、「音を端末の外へ出さない」という trk の方針とぶつかります。だから trk には入れていません。

---

## 4. trk の字幕（SRT／VTT）との違い

| | trk の字幕（💬 字幕） | 自動字幕（OS／ブラウザー） |
| --- | --- | --- |
| 出どころ | 用意した `.srt`／`.vtt`、またはフォルダの同名ファイル | 流れている音声をその場で認識 |
| 正確さ | **高い**（人が作った時刻と文） | 声・雑音・マイクで変わる |
| 遅れ | なし（「遅延」で ±0.25 秒ずつ調整できる） | 0.5〜2 秒ほど遅れる |
| 置き場所 | **trk の設定で 下・中央・上／大きさ 小・中・大** | OS／ブラウザーの設定（画面の下など） |
| 端末の外へ出るか | **出ない**（端末内で読むだけ） | 端末内（上記の対応表のとおり） |
| 画中画（PiP） | trk の字幕も付く（WebVTT に変換して `<track>`） | PiP の窓には出ない（OS の重ね表示は画面全体なので出る場合がある） |

**SRT の作り方（最小）**：

```
1
00:00:12,000 --> 00:00:15,500
ここに字幕の1行目
ここに2行目（最大4行）

2
00:00:16,000 --> 00:00:19,000
次の字幕
```

- ファイル名は曲と**同じ名前**にして同じフォルダに置くと、フォルダを開いただけで自動で見つかります（`.srt` と `.vtt` が両方あるときは `.vtt` を優先）。
- 手で選ぶこともできます：💬 字幕 →「📄 字幕ファイルを選ぶ」。選んだ字幕と遅延は**曲ごとに端末内**へ保存されます（外へは送りません）。

---

## 5. trk が中で自動字幕を作らない理由

1. **API の制約**：Web Speech API は**マイク入力だけ**を対象にしています。いま再生している音（`<video>` の中身）を渡す標準的な方法はありません。
2. **音を外に出さない方針**：trk は「曲ファイルは端末内から出ない」を守っています。音声認識を入れると、音がベンダーのサーバーへ渡る経路ができてしまいます。
3. **対応端末が限られる**：実験的な API は PC の Chrome／Edge だけで、iPhone・iPad では使えません。trk の主な使い先と合いません。
