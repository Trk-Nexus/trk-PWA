## 3. 作ったもの

### 3.1 2 つの API を 1 か所で決める

| 関数 | 役目 |
| --- | --- |
| `pipBackend(st)`（**純粋な計算**） | `"standard"` / `"webkit"` / `""` を決める。標準を先に、無ければ webkit。`prefer`（前回通ったほう）を尊重 |
| `pipRunning(st)`（**純粋な計算**） | 小窓が出ているか。標準は `document.pictureInPictureElement`、webkit は `webkitPresentationMode === "picture-in-picture"` |
| `pipHomeApp()` | iPhone／iPad のホーム画面アプリ（`navigator.standalone`／`display-mode: standalone`）を見分ける |
| `pipWebkitProbe()` | `webkitSupportsPresentationMode("picture-in-picture")` に聞く。**読み込み前（`readyState < 1`）の `false` は「分からない」**として捨てる（Safari は最初のフレームが出るまで対応を名乗らない） |
| `pipState()` | 上の 2 つをまとめて `pipBackend` に渡す形にする |
| `pipSupported()` | 押せるか（`pipBackend(...) !== ""`） |
| `pipUnsupportedKey()` | 押せない理由の言葉。ホーム画面アプリだけ `mediaPipHomeApp` |

### 3.2 入る・出る

| | 標準 | webkit（Safari） |
| --- | --- | --- |
| 入る | `pipEnterStandard()` → `await video.requestPictureInPicture()` | `pipEnterWebkit()` → `video.webkitSetPresentationMode("picture-in-picture")` |
| 出る | `document.exitPictureInPicture()` | `video.webkitSetPresentationMode("inline")` |
| 出ているか | `document.pictureInPictureElement` | `video.webkitPresentationMode` |
| 知らせ | `enterpictureinpicture` / `leavepictureinpicture` | `webkitpresentationmodechanged` |

- `enterPip()` は「まず `pipBackend()` の答え → だめなら webkit」。Safari の標準 API は
  **あるのに断られる**ことがあるので、失敗は `console.warn` で控えめに記録して先へ進みます。
- `pipEnterWebkit()` は Promise を返さないので、**最大 1.2 秒**（100ms × 12）様子を見て、入れなければ「開けなかった」にします。
- `exitPip()`／`closeMedia()` の「閉じる」側も、**標準と webkit の両方**を見ます（trk263 の「閉じても残す」が Safari でも効くように）。

### 3.3 文言（4 言語）

| キー | 何を言うか |
| --- | --- |
| `mediaPipHomeApp`（新規） | ホーム画面のアプリでは画中画を使えません（Safari で開くと使えます） |
| `mediaPipFailed`（新規） | 画中画を開けませんでした（動画を再生してから、もう一度お試しください） |
| `mediaPipHint`（書き直し） | 「PC の Chrome／Edge／Safari。スマホは非対応」→ **PC の Chrome／Edge／Safari、iPhone／iPad の Safari。ホーム画面のアプリでは使えないことがある** |

`mediaPipUnsupported`（このブラウザは画中画に対応していません）は**そのまま**残しています。

## 4. ブラウザーごとの動き（2026-11-02 時点の事実）

| ブラウザー | 標準 API | webkit API | trk264 の動き |
| --- | --- | --- | --- |
| Chrome / Edge（PC） | ○ | 無し | 標準で入る（今までどおり） |
| Chrome（Android） | ○（105+） | 無し | 標準で入る |
| Firefox | ○（153+） | 無し | 標準で入る。それ以前は 📌 が押せない（理由を title に出す） |
| Safari（Mac） | ○（13.1+） | ○ | 標準で入る。断られたら webkit |
| Safari（iPhone／iPad） | ○（14+） | ○ | 同上 |
| **Safari のホーム画面アプリ** | **×**（`NotSupportedError`。`pictureInPictureEnabled` は true のまま） | `webkitSupportsPresentationMode` が **false** | 📌 を押せなくして理由を出す |

> ホーム画面アプリの件は **WebKit bug 303885**（2025-12 起票）。`document.pictureInPictureEnabled` が
> true を返すのに `requestPictureInPicture()` が失敗するため、**要素に聞く webkit の判定が唯一正しい**、
> という報告です。trk はその判定に合わせてボタンを閉じます（コンテナ側が直れば自動で使えるようになります）。

## 7. まだ実機で見ていないこと（Safari）

1. **Mac の Safari**：📌 で小窓が出る／✕ で戻る
2. **Mac の Safari**：📌 → プレーヤーを閉じる → **小窓が残って動き続ける**（音もそのまま）
3. **iPad／iPhone の Safari**：上の 2 つ
4. **ホーム画面のアプリ**：📌 が押せないまま、長押し／ホバーで理由が出る
5. Safari で小窓を出したまま「ここにも表示」「画中画を終了」が効く
6. Safari で小窓を出したまま曲送り → 小窓の曲が変わる（`video` 要素そのものを映すため）
7. Safari の小窓の ✕ で音が止まり、映像が戻る（`webkitpresentationmodechanged` の後始末）

### 7.1 分かっている制約

- **ホーム画面アプリ（iPhone／iPad）では使えません**（ブラウザー側の不具合）。Safari で開けば使えます。
- trk の `<video>` は**2px の見えない要素**（絵は canvas に描いています）。Chrome ではこの形で動いていますが、
  **Safari が同じ形で小窓に入れるかは実機で確認が要ります**。もし入れなければ、小窓の間だけ実寸にする等の手当てを次の回に。
- 小窓の見た目（位置・大きさ・閉じるボタン）はブラウザーが持ちます。ページからは変えられません。
- Firefox 153 より前は標準 API が無いので、📌 は押せません（自前の小窓ボタンがあるため）。
