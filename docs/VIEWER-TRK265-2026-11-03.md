## 2. 作ったもの

### 2.1 M1：閉じる側を 1 か所に

```js
async function leavePipBoth() {
  try { if (document.pictureInPictureElement) await document.exitPictureInPicture(); } catch (_) {}
  try {
    const v = core.video;
    if (v && typeof v.webkitSetPresentationMode === "function" &&
        v.webkitPresentationMode === "picture-in-picture") v.webkitSetPresentationMode("inline");
  } catch (_) {}
}
```

- `exitPip()`（案内の「画中画を終了」・ボタン）と `closeMedia()`（閉じる／ゲーム開始／設定オフ）の**両方**から呼びます。
- **if / else をやめた**ので、標準が例外・reject でも webkit を必ず試します。
- `pipActive` は **`pipActuallyOn()`（実際に出ているか）** に合わせるので、閉じきれていなければ「画中画を終了」のまま（嘘をつかない）。
- `closeMedia()` は `await` できないので投げっぱなしにしますが、**内部で全部 catch** するので**未処理の reject は出ません**（レビューの指摘も解消）。

### 2.2 R1：待ち方をイベントに

- `waitWebkitPip(ms = 2500)`：**先に待ち始めてから** `webkitSetPresentationMode` を呼ぶ（速い知らせを取りこぼさない）。
- 知らせが来なければ**上限で実際の状態**を見る（`pipActuallyOn()`）。
- `togglePip()`：`pipActive = ok || pipIsOn();`／トーストは `!pipActive` のときだけ。

### 2.3 R3：押せない理由を**見える文字**で

- `#mediaPipWhy`（`<p class="mediaPipWhy hint" hidden>`）を**操作列のすぐ下**に置き、押せないときだけ `mediaPipHomeApp` / `mediaPipUnsupported` を出します。
- ボタンには `aria-describedby="mediaPipWhy"`（出しているときだけ）＝読み上げでも理由が分かります。
- 文言（4 言語）は **macOS の Dock の Web アプリ**も含む言い方に直しました。

### 2.4 版

- `index.html` `trk-build=trk265`／`sw.js` `CACHE="trk-v2026.11.03-trk265"`。
- **設定は増やしていません**（`js/core.js` は差分 0 行＝localStorage のキーも増えていません）。
